PawStay 宠物寄养 —— 功能说明
====================================

  官网          http://127.0.0.1:8000/            演示顾客 13800000001 / pawstay123
  运营后台      http://127.0.0.1:8000/admin/      管理员 admin / admin123
  员工工作台    http://127.0.0.1:8000/staff/      手机浏览器使用，账号同后台
  经营报表      http://127.0.0.1:8000/admin/bookings/order/reports/
  健康检查      http://127.0.0.1:8000/healthz     数据库可连接返回 ok，否则 503


一、官网（未登录可访问）
------------------------
1. 首页
   品牌介绍、查空房搜索条（默认明天入住、住 3 晚）、真实统计（在售房间数、平均评分及评价数，
   无评价时显示“新店开业”）、精选房间、护理服务、预约流程、公开评价、常见问题。

2. 房间列表 /rooms/
   按宠物类型、房型、入住/离店日期筛选；带日期时只显示该时段可订房间，并在卡片上显示
   总价与连住优惠金额。房间徽标区分“狗狗专属 / 猫咪专属 / 猫狗皆可”。

3. 房间详情 /rooms/<id>/
   房间照片、面积、容量、设施、介绍；选择日期后给出逐晚明细（节假日标注规则名称）、
   连住折扣与合计，并提示是否可订。

4. 静态页面 /pages/<名称>/
   常见问题、服务协议、隐私政策、图片来源（读取 static/img/stock/credits.json）。


二、账号
--------
  注册        手机号 + 短信验证码 + 姓名 + 密码，注册后引导添加第一只宠物。
              获取短信前需先通过图形验证码；手机号已在门店建档的老客户，由前台在后台
              “开通线上账号”，避免冒名认领档案。
  短信验证码  6 位数字，5 分钟有效，最多尝试 5 次；同一手机号 60 秒内只能发送一次、每天最多
              10 条，同一 IP 每小时最多 20 条。验证码只以哈希形式存放在数据库缓存中。
              SMS_BACKEND=console 时打印到日志（开发用），aliyun 时调用阿里云短信服务。
  登录        手机号 + 密码；同一 IP 连续输错 3 次后需输入图形验证码，同一手机号连续 5 次
              错误锁定 15 分钟（数据库缓存计数）。后台登录页规则相同。
              登录后的跳转地址只允许本站链接（防开放重定向）。
  个人资料    姓名、邮箱、地址、紧急联系人。
  修改密码    需输入原密码。
  找回密码    两种方式：
              (1) 短信：手机号 + 图形验证码 + 短信验证码直接设置新密码，成功后解除登录锁定；
                  为防止枚举账号，未注册的手机号同样提示“已发送”但不会真正发送。
              (2) 邮件：输入注册邮箱，发送一次性重置链接（Django 令牌，过期失效）；
                  未配置 SMTP 时邮件打印在控制台，邮箱不存在也显示“已发送”。


三、会员中心（需登录，路径 /me/）
----------------------------------
1. 个人中心：在住 / 即将入住订单、候补登记、待评价订单、未读通知、宠物卡片，
   以及 30 天内疫苗到期提醒。

2. 我的宠物：新增 / 编辑 / 删除（已有订单的宠物不可删除）。
   字段：照片、名称、类型、品种、年龄、性别、体重（决定体型：<10kg 小型、10-25kg 中型、
   >25kg 大型）、绝育、性格（温顺/活泼/胆小/有攻击性）、健康情况、饮食习惯、过敏禁忌、
   疫苗有效期、驱虫有效期。选择照片后立即预览。

3. 在线预约 /book/
   选择宠物、房间、日期。日期使用中文日历：入住不能早于今天，选好入住后自动打开离店日历，
   离店只能晚于入住，悬停即显示“共 N 晚”；支持键盘方向键、PageUp/PageDown 翻月。
   房间或日期变化时右侧费用明细局部刷新（逐晚价格、节假日加价、连住折扣）。
   提交时校验（任一不满足给出明确原因）：
     (1) 离店晚于入住，入住不早于今天，单次不超过 MAX_BOARDING_DAYS 天（默认 60）
     (2) 房间未维护停用，适用宠物类型匹配，宠物体型不超过房间最大接待体型
     (3) 有攻击性的宠物只能入住单宠房间（容量 = 1）
     (4) REQUIRE_VACCINE=true 时，疫苗有效期需覆盖到离店日
     (5) 容量逐日校验：区间内任意一天有效订单数达到容量即为已满；离店当天可接下一单
     (6) 同一宠物同一时段不能重复预约
   并发控制：提交时对房间行加锁（SELECT ... FOR UPDATE），同一房间的并发预约串行校验，
   不会超订。
   满房时可一键登记候补（宠物 + 日期 + 期望房型）。

4. 支付 /me/orders/<订单号>/pay/
   选择微信 / 支付宝后进入收银台：先创建“待确认”流水，渠道确认后再入账。
   PAYMENT_SANDBOX=true（默认）时为本站模拟扫码页，点“模拟支付成功”即入账；
   设为 false 并配置商户密钥后，微信走 Native 扫码、支付宝走电脑网站支付，回调地址
   /pay/notify/<wechat|alipay>/。退款优先走原渠道，微信未配证书时记门店账本由财务对账。
   线上订单需在 PAYMENT_TIMEOUT_MINUTES 分钟（默认 30）内支付，页面显示截止时间；
   超时后由定时任务或打开支付页时自动取消并释放房间。
   改期后需补差价的订单状态为“待补差价”，支付页只收取差额。

5. 订单列表与详情
   按状态筛选（已预约 / 寄养中 / 已完成 / 已取消）。
   详情页：步骤条（预约成功 → 完成支付 → 办理入住 → 平安离店，含时间）、
   护理时间线（时间、内容、进食情况、健康状态徽标、健康说明、现场照片缩略图，
   点击进入灯箱，可左右切换、键盘与手势翻页）、宠物信息、房间与日期、
   订单金额 / 已付 / 待付、留言、收退款记录。

6. 自助改期 /me/orders/<订单号>/change/
   “已预约”且入住日在今天之后的订单可更换房间和日期，页面实时展示新费用、已付金额，
   以及“需补差价 ¥x”或“将退还 ¥x”。提交后：
     - 新金额低于已付：差额自动原路退款
     - 新金额高于已付：订单变为“待补差价”，跳转支付页补款
   改期同样执行第 3 节全部校验，并对房间加锁防超订。

7. 取消预约：仅“已预约”状态可取消，可填写原因。
     - 入住日之前取消：免费，已付金额全部原路退回
     - 入住当天及之后取消：扣除前 LATE_CANCEL_NIGHTS 晚（默认 1 晚）房费作为违约金，
       不超过已付金额，其余退回；取消弹窗会预先展示退款金额与违约金
   取消释放房间后自动检查候补队列。

8. 评价：订单完成后可评分（1-5）、填写评价与意见反馈；机构回复后显示在订单与官网。

9. 消息通知：支付成功、补款成功、预约已改期、已入住、护理动态、健康异常提醒（红色）、
   寄养完成（提前离店附退款金额）、预约取消、候补有房（附预约直达链接）。
   支持一键全部已读；通知链接只允许站内地址。


四、员工手机工作台（/staff/）
-----------------------------
  面向前台与护理师的手机页面，需员工账号；开启二次验证时与后台一样需先完成 TOTP 验证。
  1. 三个标签页：今日到店、在住（显示最近一次护理时间，今天未记录的会标出）、今日离店
     （含逾期），顶部可按宠物名、主人姓名、手机号搜索。
  2. 办理入住 / 离店：一键操作；提前离店自动按实住晚数重新计价并退还差额。
  3. 现场收款：仅现金 / 刷卡，收取订单待付余额。
  4. 护理记录：进食情况与健康状况用大按钮选择，常用短语（早餐、晚餐、遛弯、梳毛……）
     一键追加；可直接调用手机相机拍照，选图即预览；健康状况非“良好”时必须填写说明，
     并自动通知主人。


五、运营后台（/admin/）
-----------------------
1. 运营看板（后台首页）
   顶部快捷入口：手机工作台、经营报表、可用房间查询、门店录入订单。
   今日待入住、今日待离店（含逾期未离店）、在住 / 总床位、入住率、本月净收入
   （收款 - 退款）、待收款订单（含待补差价）、候补中、平均评分 / 待回复评价；
   今日入住与离店清单、近 3 天健康异常记录。

1a. 经营报表（订单列表右上角“经营报表”，需同时拥有查看订单与收退款流水权限）
   统计周期：近 7 天 / 30 天 / 90 天 / 12 个月 / 本月 / 自定义（最长 731 天），
   点选即刷新，修改起止日期自动切换为自定义。
   指标：净收入（收款、退款）、入住率与已售间夜、平均每间夜收入、新增订单与取消率、
   平均寄养时长、复购顾客占比。
   趋势图：柱状为净收入、折线为入住率；区间超过 62 天按月汇总。
   分析表：房型表现（订单、间夜、入住率、净收入及占比）、下单渠道、支付方式。
   导出：每日明细、订单明细 CSV（UTF-8 BOM，Excel 双击打开不乱码）。
   口径：收入按收退款流水实际发生时间统计（收付实现制）；间夜按订单覆盖的日期统计，
   含已预订未入住的有效订单。

2. 宠物主人：搜索、查看名下宠物与订单；动作“开通线上账号（生成初始密码）”。
3. 宠物档案：照片预览、按类型/性别/性格筛选、历史寄养记录。
4. 寄养房间：照片、展示名称、最大体型、面积、设施、是否官网展示；
   列表直接改价；动作“设为维护停用 / 解除停用”；显示当前入住数。
5. 价格规则：名称、起止日期（含当天）、倍率（1.20 = 上浮 20%）、启用开关。
   同一晚命中多条规则时取倍率最高的一条。
6. 寄养订单：
   - 搜索订单号、宠物、主人姓名/电话；按状态、支付状态、渠道、房型、入住日期筛选
   - 动作：前台收款（现金）、办理入住、办理离店、取消预约（按违约金规则退款）、
     取消预约（全额退款，免收违约金）
   - 提前离店：离店日改为当天（至少 1 晚），按实住晚数退款，释放房间并处理候补
   - 已付款订单修改房间或日期即为改期，保存时自动结算差价（多退少补），并提示待补金额
   - 订单详情内嵌护理记录与收退款流水；“可用房间查询”页一键带入新建订单
7. 收退款流水：只读，流水号 T/R + 时间 + 随机串，支持按方式、类型筛选。
8. 候补登记：动作“立即匹配空房并通知”。
9. 护理记录：照片缩略图、按健康状态与时间筛选；异常记录自动通知主人并更新宠物健康情况。
10. 服务评价：是否已回复、是否官网展示。
11. 站内通知：可查看与补发。
12. 权限组：前台、护理师（make seed 时创建）。
13. 二次验证（右上角“二次验证”）：扫码绑定身份验证器 App（TOTP，30 秒 6 位动态码），
    每次登录后台或工作台需输入动态码；同一动态码不能重复使用。
    ADMIN_REQUIRE_2FA 留空时生产环境强制开启、开发环境关闭。
    员工丢失手机时，由管理员在“账号安全 → 二次验证设备”删除其设备后重新绑定。
14. 照片：所有上传照片自动按 EXIF 纠正方向、去除 EXIF（含 GPS 定位）、限制最长边
    （宠物 1280px，其余 1920px）、转为 JPEG（透明图转 WebP）并随机命名；
    列表与卡片按需生成 WebP 缩略图（media/thumbs/），后台列表显示缩略图并可点开原图。


六、资金规则
------------
  订单的已付金额 = 收款流水合计 - 退款流水合计；支付状态据此自动维护：
    未支付 / 待补差价（已付 < 订单金额）/ 已支付 / 已退款。
  入住日前取消        全额退款
  入住当天及之后取消  扣前 LATE_CANCEL_NIGHTS 晚房费（默认 1，设为 0 即随时免费取消）
  提前离店            EARLY_CHECKOUT_REFUND=true 时按实住晚数重新计价并退还差额
  改期                新金额 < 已付：退差额；新金额 > 已付：待补差价
  退款渠道            原路退回到最近一次收款的支付方式


七、定价规则
------------
  逐晚价格 = 房间单价 × 当晚命中的最高节假日倍率（无规则为 1）
  小计     = 各晚价格之和
  连住折扣 = 入住晚数 ≥ LONG_STAY_DAYS（默认 7）时，小计 × (1 - LONG_STAY_RATE)（默认 9 折）
  订单金额 = 小计 - 折扣；下单时锁定，改期时按新房间与日期重新计算。


八、定时任务
------------
  manage.py expire_orders（make expire）：
    取消超过支付时限的线上未支付订单，并为候补队列中已有空房的登记发送通知。
  Docker 部署时由 scheduler 容器每 5 分钟执行一次。
  数据备份：backup 容器每天 BACKUP_AT 导出数据库与上传文件，见《04-开发与运行》。
