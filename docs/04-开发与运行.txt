PawStay 宠物寄养 —— 开发与运行
====================================

一、环境要求
------------
  Python 3.13（uv 会按 .python-version 自动选择/下载）
  uv          包管理器
  GNU Make    Windows 可用 scoop install make
  MySQL 8+    本地开发需已启动，默认连接 root@127.0.0.1:3306，空密码
  Docker      仅生产部署需要（Docker Compose v2）


二、本地开发
------------
1. 启动 MySQL
   Windows（scoop 安装）：在单独终端执行  mysqld --console
   或使用 Docker：
     docker run -d --name petowner-mysql -p 3306:3306 -e MYSQL_ALLOW_EMPTY_PASSWORD=yes mysql:8.4

2. 配置（可选）
   首次执行 make 命令会自动从 .env.example 复制出 .env；
   账号密码不同时修改 .env 中的 MYSQL_USER / MYSQL_PASSWORD。
   注意：python-dotenv 不会覆盖已存在的系统环境变量，若终端里设置过 MYSQL_* 变量，
   会优先使用终端里的值。

3. 写入演示数据并启动
   make seed     安装依赖 + 建库 + 迁移 + 演示数据
   make run      http://127.0.0.1:8000/
   演示数据按当天日期生成；跨天后看板“今日入住/离店”会变化，可 make reset-demo 重建。

4. 邮件与短信
   未配置 EMAIL_HOST 时，找回密码等邮件直接打印在 make run 的终端里。
   SMS_BACKEND=console（默认）时短信验证码不会真正发送，打印在终端日志里：
     ... WARNING apps.security.sms: 【短信验证码】13800000009 -> 123456（控制台通道，未真实发送）
   DEBUG 模式下发送接口还会把验证码返回给页面，方便本地联调；生产环境不会返回。

5. 二次验证
   开发环境默认不强制（ADMIN_REQUIRE_2FA 留空且 DEBUG=true）。如需体验：
   后台右上角“二次验证” → 用身份验证器 App 扫码 → 输入 6 位动态码完成绑定。


三、常用命令（make help 查看全部）
----------------------------------
  本地开发
    make install         安装/同步依赖（uv sync）
    make env             若 .env 不存在则从 .env.example 复制
    make initdb          创建 MySQL 数据库（已存在则跳过）
    make makemigrations  根据模型变更生成迁移文件
    make migrate         执行迁移并创建缓存表
    make setup           依赖 + 建库 + 迁移
    make run             启动开发服务器（make run PORT=9000 / HOST=0.0.0.0）
    make seed            写入演示数据（已有业务数据则跳过）
    make reset-demo      清空数据库与上传文件后重新写入演示数据
    make superuser       交互式创建管理员
    make expire          手动执行超时订单取消与候补匹配
    make images          按 scripts/fetch_images.py 清单从 Wikimedia Commons 下载授权图片
    make shell           Django shell
    make clean           清理 __pycache__ 与 staticfiles

  质量
    make test            运行全部单元测试
    make lint            ruff 检查 + 格式检查
    make format          ruff 自动格式化与修复
    make check           Django 系统检查 + 迁移缺失检查
    make deploy-check    以生产配置运行 check --deploy（需零警告）
    make collectstatic   收集静态文件

  Docker
    make docker-build    构建生产镜像
    make docker-up       启动 MySQL + Web + 定时任务 + 备份 + Nginx
    make docker-down     停止容器（数据卷保留）
    make docker-logs     跟踪日志
    make docker-seed     在容器中写入演示数据
    make docker-backup   立即备份数据库与上传文件到 backups/


四、生产部署（Docker Compose）
------------------------------
1. 准备 .env（从 .env.example 复制），至少修改：
     DJANGO_DEBUG=false
     DJANGO_SECRET_KEY=<50 位以上随机串>
     DJANGO_ALLOWED_HOSTS=pawstay.example.com
     DJANGO_CSRF_TRUSTED_ORIGINS=https://pawstay.example.com
     DJANGO_HSTS_SECONDS=31536000（确认 HTTPS 稳定后再开启）
     MYSQL_USER=pawstay（不能为 root）、MYSQL_PASSWORD、MYSQL_ROOT_PASSWORD
     EMAIL_HOST / EMAIL_HOST_USER / EMAIL_HOST_PASSWORD / DEFAULT_FROM_EMAIL
     DJANGO_ADMINS=ops@example.com（500 错误与短信发送失败等异常的告警收件人）
     SMS_BACKEND=aliyun 及 SMS_ACCESS_KEY_ID / SMS_ACCESS_KEY_SECRET / SMS_SIGN_NAME /
       SMS_TEMPLATE_CODE（阿里云短信控制台申请签名与验证码模板，模板变量为 ${code}）
     SITE_* 品牌与门店信息、SITE_ICP 备案号
   可选：LATE_CANCEL_NIGHTS（违约金晚数）、EARLY_CHECKOUT_REFUND、BACKUP_AT、
   BACKUP_KEEP_DAYS、TZ（备份容器时区，默认 Asia/Shanghai）。
   站点尚未配置 HTTPS 时将 DJANGO_SECURE_SSL_REDIRECT 设为 false。
   应用已改用 PyMySQL，镜像构建不再依赖 apt 编译 mysqlclient，一般无需 APT_MIRROR。
   若本机 Docker Desktop 未启动会导致 build 失败；也可推送到 GitHub 由 CI 构建镜像。

2. 启动
     make docker-up
   服务组成：
     db         MySQL 8.4，数据卷 mysql-data，带健康检查
     web        Gunicorn（3 个 worker），启动时自动 migrate + createcachetable；
                上传文件存放于数据卷 media；镜像内 HEALTHCHECK 访问 /healthz
     scheduler  同一镜像，每 300 秒执行 manage.py expire_orders
     backup     mysql:8.4 镜像，每天 BACKUP_AT 执行 deploy/backup.sh，
                输出到宿主机 ./backups/
     nginx      对外端口 ${HTTP_PORT:-80}，反向代理 web，直接服务 /media/，开启 gzip，
                上传大小限制 10MB

3. HTTPS
   推荐在云负载均衡或宿主机 Nginx / Caddy 上终止 TLS，再转发到本服务；
   Django 已信任 X-Forwarded-Proto，HTTPS 下 Cookie 自动带 Secure 标志。

4. 上线检查
     make deploy-check     期望输出 System check identified no issues
                           （短信未配置、二次验证未开启也会报警告）
     curl http://<域名>/healthz   期望输出 ok
   首次上线后，所有员工登录后台按提示绑定身份验证器。

5. 备份与恢复
   backup 容器每天生成两份文件，保留 BACKUP_KEEP_DAYS 天（默认 7）：
     backups/db-YYYYMMDD-HHMMSS.sql.gz      mysqldump --single-transaction 全库导出
     backups/media-YYYYMMDD-HHMMSS.tar.gz   上传的照片
   导出先写入临时文件，成功后再改名，不会留下半截备份。
   建议再用云盘 / 对象存储同步 backups/ 目录，做异地备份。
   恢复数据库：
     gunzip < backups/db-xxx.sql.gz | docker compose exec -T db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD"'
   恢复照片：
     docker compose run --rm -v "$PWD/backups:/backups" --entrypoint tar web \
       -xzf /backups/media-xxx.tar.gz -C /data

6. 告警
   DEBUG=false 时，未捕获异常（500）以及 apps.* 记录的 ERROR 日志会发邮件给 DJANGO_ADMINS，
   需同时配置 SMTP。

7. 持续集成（.github/workflows/ci.yml）
   推送到 main/master 或提交 Pull Request 时：
     test 任务    MySQL 8.4 服务容器；ruff 检查与格式、manage.py check、
                  makemigrations --check、deploy_check、全部单元测试
     docker 任务  构建生产镜像（GitHub Actions 缓存加速）、镜像内 manage.py check 冒烟测试、
                  docker compose config 校验编排文件


五、安全措施
------------
  - 生产环境强制 HTTPS 跳转、HSTS、Secure / HttpOnly Cookie、X-Frame-Options: DENY、
    Referrer-Policy、内容类型嗅探防护
  - 内容安全策略（CSP）：script-src 'self'，全站无内联脚本，frame-ancestors 'none'；
    Permissions-Policy 仅允许本站使用摄像头（工作台拍照）
  - CSRF 防护；登录、注册、支付、取消、改期、退出登录等写操作均为 POST
  - 登录：同一 IP 输错 3 次需图形验证码，同一账号 5 次锁定 15 分钟（官网与后台一致）；
    密码强度校验（Django 默认四项规则）
  - 短信验证码：图形验证码前置、哈希存储、5 次尝试上限、手机号与 IP 双维度限频；
    找回密码不暴露手机号是否注册
  - 后台与员工工作台 TOTP 二次验证（生产默认强制），动态码防重放；登录后会话重新验证
  - 上传图片：限制像素总量（防解压炸弹）、重新编码并去除 EXIF（含 GPS），随机文件名
  - 跳转地址白名单，防开放重定向；站内通知链接仅允许站内地址
  - 会员中心所有对象按当前登录主人过滤，越权访问返回 404
  - 预约与改期事务内对房间加行锁，防并发超订
  - 资金变动全部经由收退款流水（不可删除），订单支付状态由流水推导，账实一致


六、测试
--------
  make test 在 MySQL 中临时创建 test_petowner 库，结束后自动删除（136 个用例，约 15 秒）。
  测试环境使用 MD5 密码哈希以加速，生产不受影响。
  覆盖范围：
    - 宠物：编号生成、体型换算、疫苗有效期判断、删除保护
    - 房间：状态随入住离店刷新、维护停用不被覆盖、逐晚报价、节假日取最高倍率、连住折扣
    - 订单：日期与时长校验、类型/体型/性格/疫苗匹配、容量逐日校验、首尾相接、
      同宠物重复预约、支付 / 入住 / 离店 / 提前离店退款 / 取消退款、非法状态操作拦截、
      超时未支付自动取消、可用房间批量查询固定查询次数
    - 资金规则：入住当天取消扣违约金、违约金不超过已付、免收违约金、改期退差 / 补差、
      补差价支付、改期后不得早于今天
    - 候补：有房通知、取消释放后递补
    - 护理与评价：前置状态、评分范围、异常通知与宠物健康状态更新
    - 官网与账号：公开页面、健康检查、短信验证码注册、短信找回密码、登录图形验证码、
      登录限流、next 参数编码与外部地址拦截、找回密码邮件全流程、不存在邮箱不泄露
    - 安全：TOTP 算法与防重放、二次验证中间件、短信限频与错误次数、CSP 响应头
    - 图片：方向纠正、EXIF 去除、尺寸限制、缩略图生成
    - 会员中心：宠物增删改、跨用户访问 404、预约 / 实时报价 / 支付 / 改期 / 取消 /
      评价 / 候补 / 通知
    - 员工工作台：权限、三栏列表、入住 / 离店 / 收款、护理记录
    - 经营报表：指标计算、按月汇总、趋势图坐标、CSV 导出、权限
    - 后台：各列表与详情页、运营看板统计、批量办理离店、后台改期
  测试数据工厂见 apps/testing.py。


七、开发约定
------------
  1. 修改 apps/*/models.py 后执行 make makemigrations && make migrate
  2. 提交前执行 make format && make lint && make test
  3. 新增依赖：uv add <包名>；开发依赖：uv add --dev <包名>
  4. .env 含本地配置与密钥，已加入 .gitignore，不要提交
  5. 新增图片：在 scripts/fetch_images.py 中登记 Wikimedia Commons 文件名后执行 make images，
     作者与许可证自动写入 credits.json 并在“图片来源”页展示
